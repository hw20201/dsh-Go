# 远程主机

dsh-Go 连接电脑或服务器上的 DSH；对话、工作区和插件属于所连接的主机。当前 App 不提供手机本机引擎的安装、启动、Linux 环境、重置或卸载入口，打开 App 也不会自动启动手机本机引擎。

## 第一次打开

第一次打开 App 时，连接电脑或服务器上的 DSH，不在手机上安装引擎。

## 切换主机

打开对话列表，点底部的主机名，打开**切换主机**，选择一台已保存的远程主机。还没有主机时点**连接电脑或服务器**，已有时点**管理远程主机**。

点主机名左边的图标查看当前远程主机的连接状态和网络路径，支持时可手动测量延迟。

## 添加 SSH 主机

那台主机需要开着 SSH，并装好 DSH（`npm i -g @deepseek-ai/dsh`）。

1. 在远程主机页点**添加 SSH 主机**。
2. 填写**主机**、**用户名**，**端口**默认 22。名称可以留空。
3. 选择**密码**或**私钥**登录。私钥可以**从文件导入**，有口令时填**私钥密码（可选）**。密码和私钥只保存在这台手机上。
4. **实例管理**默认**托管启动**：**启动命令**默认 `dsh web`；用 nvm 安装的 DSH 可以填完整路径。已有自己管理的实例时选**只连接**，填写**远端 DSH 端口**和该实例启动链接中的 **DSH 登录令牌**。**工作目录（可选）**是新对话的默认目录；只连接模式请用绝对路径。
5. 点**测试连接**。首次连接会弹出**信任这台主机？**：在那台主机上核对指纹，一致再点**信任并连接**。
6. 点**保存**，再在主机列表里选中它。

托管模式的测试连接会启动或复用远端 DSH，测试结束后它继续运行。**只连接**只建立 SSH 隧道到远端 `127.0.0.1` 的指定端口，不自动查找实例，不执行启动、停止或重启，不读写托管状态文件；请先在远端启动实例并保持运行。连接失败时检查端口与令牌，App 不会用重启修复它。令牌和密码、私钥一样，只保存在这台手机上。

托管模式发现仍活着但启动命令不同、日志丢失的实例时，会明确停止连接而不是自动杀掉它；登录令牌被拒绝、复用端口拒连也不会授权重启。先检查配置或改用**只连接**；确实要替换 App 记录的实例时，在编辑主机的 DSH 区选择**重启托管 DSH**，确认后才停止并重启。此操作可能中断其他客户端和进行中的对话，普通**测试连接**不会执行它。已确认死亡的托管进程仍可自动补启。

**SSH 压缩**默认开启，协商认证后压缩；服务器不支持时保持未压缩传输。可在主机编辑页关闭，保存后重新建立 SSH 连接生效。

修改或删除：点主机右侧的**编辑**按钮，进入**编辑主机**，底部是**删除这台主机**。删除只移除手机上保存的设置、密码、私钥和登录令牌，远端的 DSH 和对话不受影响。

## DSH Remote

无需配置网络，连接端到端加密，适合不在同一网络的电脑。

1. 在那台主机的 DSH 里装好远程插件并登录。
2. 在远程主机页选择你在那台主机上使用的登录方式，例如「使用 GitHub 登录」，再用同一账号登录。如果页面没有列出登录方式，只显示**在浏览器中登录**，点它继续。
3. 在列表里选中在线的主机。首次连接时核对身份指纹，与主机上远程插件显示的一致再点**信任并连接**。

服务器支持时，远程主机页会出现**扫码配对电脑**：先在 App 登录 DeepSeek，点**扫码**打开系统扫码页，扫电脑 Remote 插件显示的配对二维码，核对电脑指纹后按提示输入验证码。扫码页由系统提供，相机归它使用，DSH Go 不申请相机权限；二维码在截图里时，在扫码页里从相册选图即可。也可以复制配对链接，点**粘贴配对链接**。系统扫码打不开时，会提示改用粘贴配对链接。

当前鸿蒙版没有 WebRTC，只走端到端加密的 Relay 中继，不走局域网、P2P 或 TURN。远程主机页的 DSH Remote 的**连接路径** 可选择自动或仅 Relay；**仅直连（LAN / P2P）**不可用。路径选择只影响 DSH Remote，不影响独立的 SSH 或 DSH 地址直连主机。选择在下次连接生效，已建立连接不会立刻断开；若点**按新路径重新连接**并确认，当前连接和进行中的操作可能中断。网络详情分别显示当前实际路径和下次连接所选路径，以及连接耗时和可测的往返延迟；未测量的项目不会显示为零。

<!-- nav: commonSettings,commonRemoteHost,remoteCompactHistory -->
`设置 › 远程主机 › 精简历史`

**精简历史**默认关闭。开启后，支持的 DSH Remote 主机会把历史工具参数和输出转为摘要，减少历史传输量；正文、实时回复和审批不变，也不会修改主机原始记录。切换到其他远程主机后再连回来，或重启 App 后生效；当前连接及其自动重连保留原模式，避免历史缓存混用。关闭后同样需要重新选择主机，再打开对话获取完整历史。旧主机没有该能力时仍传输完整历史，SSH 不受此设置影响。

DSH Remote 一次只连一台主机，切换会断开上一台。经 DSH Remote 连接时：只能发送图片；插件只能开关；DS Bot 和导出对话日志不可用。对话备份使用独立的传输能力，不是导出对话日志。

## 对话备份与恢复

<!-- nav: commonSettings,commonRemoteHost,backupTitle -->
`设置 › 远程主机 › 对话备份`

此功能仅支持 DSH Remote／Relay 主机，SSH 和独立的 DSH 地址直连暂不支持。源主机须声明 `session.transfer` 的导出（export）能力，目标主机须声明导入（import）能力；两端分别检查，旧版插件缺少相应能力时会说明。

连接源 Remote 主机，选择工作区和单条对话或**整个工作区**，点**备份到手机**。切换到目标主机后，重新打开该页，选择目标已有工作区，再点手机上的备份恢复。单条对话的备份传输上限为 8 MiB；整个工作区按对话逐条备份，不能绕过单条限制。

备份文件和清单在 App 私有目录加密保存，密钥由系统安全存储保护；卸载 App 或清除应用数据会丢失备份。只保存通过长度和 SHA-256 校验的完整条目；整批中断不会丢弃已完成的条目。每次恢复都新建对话并恢复完整历史快照，不覆盖已有对话，也不合并后续消息；备份不包含附件、工作区源码或跨对话关系。

提交断线或结果不明时，页面保留**待核对的恢复**。使用原 Remote 设备身份连接原目标主机点**查询**；服务端结果仅保留约五分钟，查不到时先在目标端检查，不会自动重导。确认已检查后可清除待确认记录；再导入可能产生副本。若显示“历史已恢复，未加入工作区”，按给出的对话 ID 查找，不要重复导入。删除手机备份不会删除主机上的对话。

当前 Remote 一次只连接一台主机，所以采用“先备份到手机、再切换恢复”，不提供两台主机同时在线直传。
